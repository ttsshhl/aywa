# Айва

Маркетплейс готовых проектов: приложения, игры, боты и сервисы с выручкой.
Одна статическая страница, вся логика в браузере, данные в Supabase.

```
index.html    приложение целиком: разметка, стили, логика
schema.sql    таблицы, RLS и бакет для скриншотов
favicon.svg   иконка
CNAME         домен для GitHub Pages — впишите свой
404.html      любой подпуть возвращает на витрину
.nojekyll     чтобы Pages не обрабатывал файлы через Jekyll
robots.txt    и sitemap.xml — поправьте адрес под свой домен
```

## 1. Supabase

1. **База.** SQL Editor → вставить `schema.sql` целиком → Run.
   Скрипт создаёт таблицы, политики доступа и публичный бакет `shots`.
2. **Себя в владельцы.** В конце `schema.sql` есть закомментированный
   `insert into public.owners` — раскомментируйте со своей почтой и выполните
   после первого входа в приложение, иначе панель владельца увидит только свои сделки.
3. **Ключи.** Project Settings → API. `Project URL` и `anon public` вписать
   в начало `<script>` в `index.html`:

```js
const SUPABASE_URL = 'https://xxxxx.supabase.co';
const SUPABASE_ANON_KEY = 'eyJ...';
```

`anon`-ключ публичный, его видно в исходниках страницы — так и задумано,
доступ ограничивают политики RLS из `schema.sql`. Ключ `service_role`
в этот файл класть нельзя.

4. **Адреса возврата.** Authentication → URL Configuration:
   Site URL — адрес сайта, в Redirect URLs добавить его же.

## 2. Вход через Яндекс ID

У Supabase нет готового провайдера «Яндекс», поэтому заводим свой.

1. `oauth.yandex.ru` → создать приложение, платформа «Веб-сервис»,
   права **Доступ к адресу почты** и **Доступ к имени и фамилии**.
2. Redirect URI приложения = Callback URL из формы Supabase:
   `https://<проект>.supabase.co/auth/v1/callback`
3. Supabase → Authentication → Providers → **Create Custom Auth Provider**:

   | Поле | Значение |
   |---|---|
   | Provider Identifier | `yandex` |
   | Configuration Method | **Manual configuration** — авто-поиск не сработает, у Яндекса нет `/.well-known/openid-configuration` |
   | Authorization | `https://oauth.yandex.ru/authorize` |
   | Token | `https://oauth.yandex.ru/token` |
   | User info | `https://login.yandex.ru/info?format=json` |
   | Scopes | `login:email,login:info` |
   | Client ID / Secret | из приложения Яндекса |

4. Если идентификатор отличается от `yandex`, поправьте в `index.html`:

```js
const YA_PROVIDER = 'custom:yandex';
```

Вход по почте с паролем работает независимо и настройки не требует.

## 3. Скриншоты

Продавец добавляет до шести снимков в форме объявления. Картинки ужимаются
в браузере до 1600 px по длинной стороне и уходят в бакет `shots` по пути
`<id пользователя>/<id объявления>/<n>.jpg`. Политики из `schema.sql`
разрешают запись только в свою папку, чтение — всем.

Бакет публичный: ссылки вида `/storage/v1/object/public/shots/...`
открываются без токена, это нужно для показа галереи гостям.

## 4. GitHub Pages

```bash
git init
git add .
git commit -m "Айва"
git branch -M main
git remote add origin https://github.com/<логин>/<репозиторий>.git
git push -u origin main
```

Settings → Pages → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)`.
Через минуту сайт открывается по адресу `https://<логин>.github.io/<репозиторий>/`.

Если публикуете в подпапку репозитория (не в корень домена), удалите `CNAME`
и `404.html`: редирект на `/` уведёт с подпапки.

## 5. Свой домен

1. В `CNAME` уже вписан домен без протокола, одной строкой: `aywamarket.ru`.
2. Settings → Pages → Custom domain — тот же домен, сохранить.
3. У регистратора:

   **Апекс** (`aywamarket.ru`) — четыре A-записи:

   ```
   185.199.108.153
   185.199.109.153
   185.199.110.153
   185.199.111.153
   ```

   и, если провайдер умеет IPv6, четыре AAAA:

   ```
   2606:50c0:8000::153
   2606:50c0:8001::153
   2606:50c0:8002::153
   2606:50c0:8003::153
   ```

   **`www`** — CNAME на `<логин>.github.io.` (с точкой в конце, если поле её требует).
   Тогда `www.aywamarket.ru` сам переедет на апекс, GitHub делает это редиректом.

4. Дождаться проверки домена и включить **Enforce HTTPS**. Сертификат
   выпускается автоматически, обычно за 15–60 минут; DNS расходится до суток.
5. Поменять адрес в `robots.txt` и `sitemap.xml`.
6. Вернуться в Supabase → URL Configuration и заменить Site URL и Redirect URLs
   на новый домен, иначе после входа через Яндекс вернёт на старый адрес.
